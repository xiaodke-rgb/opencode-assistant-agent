# assistant 派单工作流

硬约束由 assistant 插件执行（plan 全类别 / build 只守网页）；本 skill 只教顺手流程。被守卫拦下时，按其提示行动——不要换工具、换写法去绕。

## 何时派

- **查证、检索、网页搜索 → 派 assistant**（plan 场次一律）。
- **命令类诊断也派**：assistant 有只读 shell（`ls` / `stat` / `pwd` / `wc` / `file` / `which` / `date` / `git status` / 限长 `git log --oneline`）。
- **plan 场次可直查的例外**：1–2 个明确路径的小文件、明确 URL 的 `webfetch`、`glob` 找文件——以插件额度为准（每轮直查池 3 次），本 skill 不维护第二套阈值。
- **build 场次的例外（重要）**：只有网页类（`websearch` / `webfetch`）派 assistant；读文件、找文件、翻日志、跑命令、改代码全部自己干——那是施工本体。

## 怎么派

- 只给「问题 + 已知范围」（路径 / 关键词 / 已知线索），不倒整段对话。
- 明确要它回：**结论 + 依据 + 笔记 id**；笔记系统不可用时让它把完整结论写进回复，别只给 id。
- 一次派一件事；多路查证按序来，不要并行派多个 assistant 查同一件事。

模板：

> 问题：〈要查什么〉；已知范围：〈文件 / 目录 / 关键词 / 线索〉；要求：回结论 + 依据 + 笔记 id。

## 怎么收

- 先看结论；够用即止，**不重读它的检索过程**。
- 不够细：按笔记 id 读笔记正文。**本机限制：`knowledge.show` 只看得了 plan 类型；读 note 正文要用 `knowledge.list`（返回含 body）。**
- 结论要落到你的后续动作里（引用、复述、汇报时点名），别让它白跑。

## 被守卫拦下怎么办

按拒绝文案分三种：

1. `[assistant 守卫] 拦截：…`（直接拒类）→ **改派 assistant 子代理**；不换工具、不换写法重试。
2. `[assistant 守卫] 施工类操作…` → 请用户切 **build** 模式再执行；不要绕过。
3. `[assistant 守卫] …额度（N 次）已用完` → 三选一：派单 / 把多次查询合并成一批派给 assistant / 请用户在本轮消息里加豁免词（默认 `#nocap`）。

另外：

- 被拒后**只派 assistant**，不要改派 explore/general（其他子代理仅在用户点名时用）。
- 同类连续被拒 3 次会收到「勿重试」文案——立刻停手派单。
- 派单失败（子代理报错 / 超时）：把错误原文交给用户，不自动改派、不自己顶上硬查。

## 不要做的

- 不重复写 assistant 已经写好的笔记。
- 不把本 skill 当摆设：硬线在插件；被拦了就派单，不要花式绕。
- build 场次不要把读 / 找 / 日志 / 命令类派出去。
