# scout 派单工作流

硬约束由 scout 插件执行（plan 全类别 / build 只守网页）；本 skill 只教顺手流程。被守卫拦下时，按其提示行动——不要换工具、换写法去绕。

## 何时派

- **默认派**：查证、检索、网页搜索、命令诊断（plan 场次一律）。
- 子代理的读取/检索/试错不进主代理上下文，成本只在最后几行——能派就派；但派单本身要短（见下）。
- **自己干还是派（动手前先预判调用次数）**：预计 1~2 步、最多 3 次小直查（小文件 read、glob、单个 URL、一条轻量只读命令）、且不需要留出处 → 自己做；更多，或要读大文件（>30KB）、多个文件、翻日志、全库检索、抓多个网页 → 直接派。
- plan 的直查额度是**每轮 3 次池**（会话另有总额：读 30 / 网 10 / 命令 12），由插件执行，skill 不另立阈值；撞额度或撞硬拦立刻转派，不换写法重试。
- **build 场次**：只有网页类（`websearch` / `webfetch`）派；读文件、找文件、翻日志、命令、改代码全部自己干。

## 怎么派

- 派单就是 prompt，必须短：**≤10 行、≤300 字**；不贴对话、不贴代码、不贴日志。
- 一次可装多件，按「体积 + 操作量」控：预计总答案 ≤600 字、每条只需 1~2 次小操作 → 不管主题是否相同都合并成一批（一般 1~5 条，每条一句）；能并进同批的单条小问题不要拆单。
- 预计每条都要复杂操作、长答，或合计步骤会挤占 24 步 → 拆批，先派最关键的一批。
- 回复格式**不另定**：按 `agents/scout.md` 的「怎么回」（结论带 `path:line`、笔记/缺/假设必回、无写「无」、≤10 行/≤700 字/每条 ≤100 字）。
- 不要写「照原文抄」；要证据就写「指到行」，原文由主代理按行号自己看。
- 复用会话：同一工作流、同一批文件、同一问题链，且上次的 `sessionID` 还在手边 → 带上继续；换主题、换项目，或 id 已丢（压缩/重启）→ 新开。并行多个单时各自新开，同一 id 不能并发用。

模板：

> 问题：〈1~5 条，每条一句〉；已知范围：〈文件 / 目录 / 关键词 / 线索〉；按你的回复格式回。

## 怎么收

- 结论自足即停：**不读笔记、不重跑检索、不为「确认」再派一单**。
- 要核对：按 `path:line` 定向读关键几行，别整段回读。
- 笔记只在需要明细时读：≤2 条通常「无」，3~5 条是正文，>5 条或大文件/清单/表格是索引；结论自足就不读。本机限制：`knowledge.show` 只支持 plan，读 note 正文用 `knowledge.list`。
- 缺/假设非空：能自己补就补，不能就追问一次；仍缺如实告诉用户。

## 被守卫拦下怎么办

按拒绝文案分三种：

1. `[scout 守卫] 拦截：…` → **改派 scout**；不换工具、不换写法重试。
2. `[scout 守卫] 施工类操作…` → 请用户切 **build** 再执行；不要绕过。
3. `[scout 守卫] …额度（N 次）已用完` → 三选一：派单 / 合并成一批派 / 请用户加豁免词 `#nocap`。

另外：

- 被拒后只派 scout，不要改派 explore/general（仅用户点名时用）。
- 同类连续被拒 3 次会收到「勿重试」——立刻停手派单。
- 派单失败（报错/超时）：错误原文交给用户，不自动改派、不自己顶上硬查。

## 不要做的

- 不重复写 scout 已写好的笔记。
- 不把短查询拆成多次派单，也不为「再确认一下」重复派单。
- build 场次不要把读 / 找 / 日志 / 命令类派出去。
- 不换写法绕守卫。
